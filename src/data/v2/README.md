# Exercise DB v2

Greenfield rebuild per `atlas-v2-build-plan.md`. Fixed curated library — see
the "Decision" section of the plan for what that does and doesn't rule out.

## Files

- `types.ts` — the `Exercise` shape and its controlled-vocabulary unions
  (`Muscle`, `EquipmentItem`, `EquipmentType`, `SplitTag`, `Tier`). Add new
  values to the unions here first; everything else follows.
- `muscles.ts` — canonical muscle list with display names + body region.
- `equipment.ts` — canonical equipment list, plus `equipmentGroups`, which
  maps the coarse onboarding question ("machines / dumbbells / barbell /
  calisthenics") to the granular `EquipmentItem[]` each group unlocks.
- `exercises.ts` — **the canonical library, 499 exercises.** This is a merge
  of two sources — see "Where exercises.ts comes from" below.
- `exercises.curated.ts` — the original 77 hand-authored exercises (rich
  attributes, precise muscle involvement, curated cross-movement
  substitution groups). This is the source of truth for the curated half
  of `exercises.ts` — edit exercises here, not in the generated file.
- `muscleTargets.ts` — per-split muscle-set volume targets for the session
  compiler.
- `substitutes.ts` — instant substitution lookup off `substitutionGroupId`.
- `integrityCheck.ts` — run with `npx tsx src/data/v2/integrityCheck.ts`
  before every commit that touches exercise data. Flags: duplicate ids,
  zero primary muscles, muscle refs outside the controlled vocabulary,
  involvement values outside 0-1, `defaultRepRange` with min > max, empty
  `equipmentNeeded`/`splitTags`, and substitution groups with only one
  member (not a hard error — see below).

## Where `exercises.ts` comes from

`exercises.ts` is generated by `data_migration/generateFullV2Library.ts`,
which merges:

1. The 77 hand-curated exercises (`exercises.curated.ts`) — rich, precise,
   built for the v2 schema from scratch.
2. All 422 exercises from the v1 database (`src/data/exercises.ts`), run
   through the adapter (`src/utils/adaptV1ToV2.ts`) to fit the v2 shape.

**To regenerate** (after editing `exercises.curated.ts` or the v1 source):

```
npx tsx data_migration/generateFullV2Library.ts > src/data/v2/exercises.ts
```

Don't hand-edit adapted entries directly in `exercises.ts` — fix the source
(either `exercises.curated.ts` or the adapter's mapping tables) and
regenerate, or your fix disappears on the next regeneration.

### Known precision loss on the 422 adapted exercises

The adapter is documented in full in `adaptV1ToV2.ts`, but the headline
limitations, since they affect real app behavior:

- **"shoulders" always maps to front-delts only.** v1 has no delt-head
  distinction, so side-delts and rear-delts volume can go uncredited for
  adapted entries. This is a real, observed gap — the session compiler will
  report an honest shortfall warning for side-delts on equipment-restricted
  sessions built mostly from adapted exercises, and it should, because it's
  telling the truth about what the data can support.
- **`equipmentNeeded` is one representative item per broad equipment type**,
  not v1's actual granular equipment (v1 doesn't track that at all — it's
  "machine" or "cable" with no further detail).
- **`substitutionGroupId` falls back to `movementId`** for adapted entries,
  vs. the curated set's deliberately cross-movement groups. In practice
  this works better than expected — v1's own `movementId` taxonomy already
  groups related variants for a lot of movements — but running the
  integrity checker against the full 499-exercise set currently reports
  **220 exercises with no swap candidate** (a singleton substitution
  group). That's not a bug, it's an honest count of how many adapted
  exercises don't have a same-`movementId` sibling in v1's own data.
  Closing this fully would mean hand-assigning cross-movement
  `substitutionGroupId`s the way the curated 77 have — real work, not
  something the adapter can infer.

None of this blocks using the merged library — the session compiler and
swap feature both run cleanly against all 499 — but don't assume adapted
entries are as precise as the curated ones. If you're deciding where to
spend hand-curation effort next, this file (run the integrity checker,
look at the singleton list) is where to start.

## Note on `defaultRepRange` for time-based exercises

`plank-bodyweight` and a few other curated static-hold exercises reuse
`defaultRepRange` for a hold duration in seconds rather than reps. Flagged
in the curated file — see that file's comments for detail.

## Extending the curated set

1. Pick (or create) a `movementId`.
2. Add one `Exercise` record per equipment variant to `exercises.curated.ts`
   that exists in your gym context, sharing that `movementId`.
3. Assign `substitutionGroupId` to match any other exercise that hits the
   same primary muscle with a similar `mechanic`.
4. Regenerate `exercises.ts` (command above) and run the integrity checker.
